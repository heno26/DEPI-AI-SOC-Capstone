# DEPI P5 — Unified SOC Log Intake (Week 2 Add-on)

**Status: Local test candidate (v0.1.0).** This is an *add-on*, not a replacement for any `Core` file. It preserves the original project architecture and runs your current `Core/analysis.py`, `Core/grounded_detection.py`, `Core/validator.py`, and local Ollama client. The SIEM/OpenObserve integration is intentionally unchanged.

## 1. What it actually does

`Local file(s) → existing log_parser → per-event source classifier → existing Python grounding/guardrails + specific Plink facts → local Mistral → existing validation & new Plink review checks → human-review-required reports`

Each event is assigned `windows`, `linux`, `network`, `wazuh` or `unknown`. Confidence and the reason are recorded. Unknown/conflicting events are *not* sent to the AI in this version; there is no blind classification or automatic assertion of compromise.

**Supported signatures in this candidate:** structured Windows Sysmon/EVTX-export JSON and EventID text; Linux syslog/auth/auditd and Linux process events; Zeek structured conn/DNS events and header-bearing raw TSV; Apache combined access logs and structured HTTP records; selected generic network key=value; Wazuh alert envelopes with or without identifiable underlying source. **Not supported as native input:** binary `.evtx` (export to JSON first), arbitrary binary PCAP, raw ZIP archives, and all possible proprietary vendor log formats.

The module keeps one source SHA-256 and maps `E001...` to any original `evidence_id` or an optional `source_map` generated by the `mix` command. The original files are read-only. AI input and result copies mask several standard secrets, including Plink `-pw`, JSON password/token fields and Basic/Bearer tokens. Review redaction before using on sensitive production data; it is not a comprehensive DLP solution.

## 5. Create a single mixed QA file

Choose an existing output directory, then run:

```powershell
python -B unified_soc.py mix --output "Data\mixed_week2_qa.json" "Data\Real-Datasets\Windows-Attacks\RT-01-C2\RT-01-C2-plink-focused.json" "Data\Real-Datasets\Linux-Attacks\LT-02-Privilege-Escalation\LT-02-normalized-focused.log" "Data\Real-Datasets\Network-Attacks\NT-01-Port-Scanning\NT-01-focused.json"
python -B unified_soc.py inspect "Data\mixed_week2_qa.json"
```

`mix` never overwrites a file. Its **derived, sanitized** JSON wrapper contains a per-event `source_map` (original file name/hash/ref) and the constituent records. It is a QA/replay file, *not* a real live attack or a production SIEM alert. No AI is run by `mix` or `inspect`.

Only after checking the source decisions:

```powershell
python -B unified_soc.py analyze "Data\mixed_week2_qa.json"
```

The engine groups events by family, applies existing Python helpers separately for each batch, then asks local Mistral for **separate family drafts** and creates one consolidated report. It deliberately **does not assert cross-host/cross-source correlation** without verified join keys.

## 6. Results

Running `analyze` writes only inside existing output directories:

- `Results\AN-*\` — each standard analysis (original Core output, plus `unified` evidence and flags).
- `Results\UNIFIED-*\manifest.json` — per-event source routing, confidence, original provenance, number of AI calls, omitted evidence.
- `Results\UNIFIED-*\report.md` — one mixed-source draft with the per-family AI text, validation checks and limitations.
- `Validation\validation_log.csv` — existing Core record of all validation flags.

**Caution:** The folder appears after model processing completes. If a run fails midway, any earlier `AN-*` outputs remain. Do not delete them. A `No flags` result is not proof of semantic correctness.

## 8. Limitations / release gate

- Only the supplied parser rules and new deterministic signatures are covered. Unknown log schemas abstain; no universal guarantee of correct classification.
- Time spans and attack success are never guessed. Zeek aggregation is only as trustworthy as supplied source-provenance verification; full capture hashing is a separate job.
- If a large input is split (16 events per call by default, maximum 12 calls), cross-batch behavior is not fully correlated. Read `events_sent_to_ai` in the manifest to detect context truncation.
- Review any unrecognized secret formats prior to model use; generic masks can never guarantee perfect redaction.
- Wazuh/OpenObserve deployment and Webhook acceptance were **not** exercised in these tests. Week 3 SOAR is outside the scope of this add-on.
- The code does **not** install the previous `grounded_detection_RT01_fix.py`, because that candidate showed an unintended prompt-guidance regression. RT01 improvements here are injected via bounded, scoped pre-AI notes and post-AI review flags without altering the existing Core implementation.

**Acceptance:** Real Windows, Linux and Network logs must each pass source attribution + meaningful evidence review + human-checked Mistral output, *then* mixed-file source routing and model review must pass before any SIEM integration is reconsidered.
